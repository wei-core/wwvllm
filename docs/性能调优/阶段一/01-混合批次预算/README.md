# 调优 01：限制混合批次 Prefill token（已否决）

## 数据与假设

此前阶段一对照在固定 `max_num_batched_tokens=512`、chunk=512 的错峰负载中，观察到全请求 ITL P95 为 55.70 ms，原版为 5.36 ms；阶段一每轮有 5 次混合步，最长停顿虽缩短，更多 token 间隔落在混合步上。理论假设是：**有 Decode 时限制同一混合批次的 Prefill token 数，可以缩短每次混合 forward，从而改善 ITL P95**；这种限制可能增加调度次数、增加 TTFT、降低吞吐，因此必须实测。

## 实验方案

基线为 `ae4dff1`，在当前包含前三阶段的代码上仅启用第一阶段路径，推测解码关闭。实验增加 `max_mixed_prefill_tokens`，设为 128：仅在已选 Decode 或 Speculative 请求的轮次内限制 Prefill token 总数；纯 Prefill 仍可使用完整统一预算，设 0 时保持原行为。Decode、Prefill 和 KV 管理仍沿用原有架构。完整实验补丁见 [experiment.patch](experiment.patch)；因为结果不佳，该补丁没有合入生产代码。

对称顺序：基线 → 128 → 128 → 基线，各启动独立进程，每种负载预热一次，再测 3 次，即每组 6 次；测量驱动及原始数据位于本目录。模型 Qwen3-0.6B BF16，RTX 5060 8 GiB，TP=1，CUDA Graph 开启；三方共同 `max_num_batched_tokens=512`、`prefill_chunk_size=512`、`max_model_len=2048`、`max_num_seqs=8`、`gpu_memory_utilization=0.60`、temperature 0.6、忽略 EOS。GPU 共享桌面，时钟未锁定。

短输入批次 4×(128 输入、32 输出)；长输入批次 4×(1024、16)；错峰先提交一条 (64、64)，在其输出至少 4 token 的 step 结束后加入两条 (1024、16)。三类负载均完整完成。TTFT/TPOT 为请求中位数再取六轮中位数；ITL P95 为每轮所有间隔 P95 再取六轮中位数；首请求最大 ITL 为六轮最大值的中位数。驱动是本地 `step()`，不是网络服务压测；不同调度改变随机数消费，输出内容不用于精度对照。

## 结果

| 场景 | 指标 | 基线 | 限制 128 | 变化 `(128/基线-1)` |
| --- | --- | ---: | ---: | ---: |
| 短输入 | 输出吞吐 token/s | 615.63 | 617.21 | +0.26% |
| 短输入 | TTFT P50 ms | 54.49 | 54.02 | -0.86% |
| 短输入 | ITL P95 ms | 5.18 | 5.22 | +0.70% |
| 长输入 | 输出吞吐 token/s | 110.05 | 42.67 | **-61.23%** |
| 长输入 | TTFT P50 ms | 331.80 | 771.27 | **+132.45%** |
| 长输入 | ITL P95 ms | 55.73 | 57.58 | +3.31% |
| 长输入 | 混合调度步数 | 7 | 24 | +242.86% |
| 错峰 | 输出吞吐 token/s | 156.05 | 83.59 | **-46.43%** |
| 错峰 | TTFT P50 ms | 165.56 | 430.92 | **+160.29%** |
| 错峰 | TPOT P50 ms | 8.88 | 17.36 | +95.43% |
| 错峰 | ITL P95 ms | 53.75 | 54.84 | +2.02% |
| 错峰 | 首请求最大 ITL ms | 58.70 | 57.27 | -2.43% |
| 错峰 | 混合调度步数 | 5 | 16 | +220.00% |

变化的负值对时延代表改善，对吞吐代表下降。短批次无混合步，约 1% 内差异更可能是运行波动。限制 128 的错峰首请求最大间隔略小，但全请求 P95 未改善，同时吞吐和 TTFT 显著恶化。**结论：拒绝此候选，不改变默认配置，也不在生产代码保留此开关。** 数据支持混合次数增加与整体退化同时发生；不能仅凭这组数据将因果完全归结于某一种内核或调度开销。

## 正确性

实验时，调度、概率采样及异步 CPU 测试 16 项通过；真实 Qwen3 GPU 测试通过，包括限制开启后的贪心输出与未限制参考一致。实验只验证本次覆盖的场景，不代表所有并发、TP 及异常情况。

## 复现

在独立临时目录将 `ae4dff1` 导出为 `wwvllm`，使用 `patch -p1` 对副本应用 [experiment.patch](experiment.patch)，避免修改工作区；使用 [compare.py](scripts/compare.py) 以 `--engine stage1 --mixed-prefill-limit 128` 测量实验版，基线省略该参数。两次进程分别指定不同输出文件，按照上述对称顺序运行。原始文件中的 `package_path`、配置、时间戳和混合步数保留实际测量证据。
