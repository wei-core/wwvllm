# 阶段二实验 01：有界 Draft KV 复用

## 数据与方案

此前 [阶段二对照](../../../性能对照/阶段二/README.md) 的短批次 Draft 接受率约 97%–100%，但推测吞吐仅约 13.67 token/s；目标验证次数已经降低，而 `DraftRunner.propose` 每轮从全部已提交 token 重建 Hugging Face 独立 KV。假设：复用 Draft KV 能减少长前缀重复计算，不改变目标验证及概率校正。

实验脚本保留最多 8 条请求的独立 Draft 缓存；下次提案检查 token 最长共同前缀，裁剪至已提交序列末尾之前，再计算余下 token。相互独立的缓存、目标 KV 和校正算法保持不变。它是实验代码而非生产实现：尚未覆盖按字节预算、请求完成和取消时及时释放、异常以及全部抢占路径，不能用于服务。

## 同条件实测

基线固定 `afe48dd`，均使用独立进程、Qwen3-0.6B 同模型 Draft、K=4、RTX 5060 8 GiB、BF16、temperature=0.6，预热一次后每种负载重复两次；先运行基线，再运行候选，并非交错 ABBA。共享 GPU 环境结果可能受波动影响。以下为两轮均值，吞吐按输出 token 计。TTFT/TPOT 单位秒，变化为候选相对基线。

| 负载 | 基线 token/s | 候选 token/s | 吞吐变化 | TTFT 基线→候选 | TPOT 基线→候选 |
|---|---:|---:|---:|---:|---:|
| 4×128→32 | 14.90 | 14.51 | -2.58% | 0.05486→0.05716 | 0.27538→0.28266 |
| 4×1024→16 | 12.73 | 12.96 | +1.86% | 1.82905→1.84895 | 0.10679→0.10344 |
| 交错 64→64 与 2×1024→16 | 12.97 | 13.52 | +4.21% | 1.24376→1.24670 | 0.17391→0.16804 |

每次 `step` 内多个 token 共享观测时间，因此 TPOT/ITL 是 step 粒度估计，不代表真实逐 token 间隔。缓存运行期间 `nvidia-smi` 曾观察到约 7507 MiB，基线约 7126 MiB；是不同时间的整卡占用快照，不是精确峰值增量。同尺寸 Draft 只说明此测试环境，不代表较小 Draft 的表现。重复数较少，且实验顺序非 ABBA，不能将小幅差异视为确定性收益。

## 正确性及决定

真实模型在 greedy 下针对全部接受、多个拒绝位置和两个请求隔离的候选 token、概率近似检查通过，见 `scripts/check_candidate.py`。这不证明随机采样的统计分布等价；两组随机输出哈希部分不同，缓存导致的数值路径变化是可能原因之一。未覆盖取消/异常释放及服务长时间运行。

结论：短批次退化且收益较小，候选也缺少安全生命周期，**不合入运行时代码**。保存实验脚本和原始数据以便后续围绕调度中的逐请求串行 Draft 开销继续研究。文件：`scripts/candidate.py`、`scripts/check_candidate.py`、`data/baseline.json`、`data/candidate.json`；对照驱动为 `docs/性能对照/阶段二/scripts/three_way_compare.py`。

复现：先用 `git archive afe48dd` 建立独立的 `wwvllm` 包目录并设为 `PYTHONPATH`，用同一 Python 和设备依次运行原对照驱动与 `candidate.py --engine stage2 --repeats 2 --output ...`；可独立运行 `check_candidate.py`。
